## Source repository distribution

The tracked source tree includes `package.json` and `package-lock.json` as dependency references. It does not include npm package implementations from `node_modules/`, generated website bundles from `dist/`, downloaded browser/tool binaries, or third-party font/image assets. GitHub Actions workflow entries also reference external actions; their implementations are not copied into this source tree. The local declaration for `turndown-plugin-gfm` describes imported API types rather than including the package implementation.

No separate third-party notice file is included for dependency packages that are only referenced, not redistributed in this source tree. This does not change those packages' licenses or license them under the project's MIT terms. `npm ci` downloads them separately. The license/notice material supplied varies by package and may be incomplete; inspect each included package's metadata and actual license/notice files, and resolve missing material before redistributing it. Example links point to example.com; synthetic image/document bytes are generated by tests rather than checked-in third-party media.

The exact dependency versions and package integrity values are recorded in [package-lock.json](../package-lock.json). Declared license identifiers in package metadata are useful inventory inputs, not substitutes for reading the applicable license and notice files.

## Building or redistributing dependencies

A generated website bundle, an archive containing `node_modules/`, a container image, a packaged application, or a separately distributed generated document has a different contents inventory. The source-repository scope above does not qualify those distributions. Before distributing one, identify the exact included components (including code already bundled inside dependencies), inspect their license/notice material, and include the required notices in the actual artifact. Do not assume that a successful build copies all required notices.

Revisit the source review if dependency code, copied snippets, fonts, icons, example documents or other external assets are added to the tracked tree. Preserve existing attribution and investigate unclear provenance before publication. Dependency changes also require a fresh review for any distribution that includes them. A clean vulnerability audit is not a license review.
